# Obsidian、微信流与手机聊天记录迁移

[项目介绍](../README.md) · [安装教程](setup.md) · [日常使用](usage.md) · [MCP 工具参考](tools.md)

## Obsidian与原版微信流

1. 使用用户已有Obsidian vault；没有时创建用户指定目录，在Obsidian里将其作为知识库打开。
2. 新部署使用 `setup_backend.py --apply --vault <目录>`配置；现有机器继续使用已有知识库路径。普通会话导出后将Markdown及附件按用户目标写入知识库；已有笔记更新前保留历史版本。
3. 用户需要微信原生分享入口时，从[微信流官方项目](https://github.com/freestylefly/WeChatBridge)查找当前Windows安装方式，安装后按[官方使用指南](https://github.com/freestylefly/WeChatBridge/blob/main/USAGE.zh-CN.md)设置入口和场景。安装与分享组件按当前系统状态配置。
4. 在微信里选中需要转存的消息，合并转发到其他应用，选择微信流及目标，生成可打开的笔记。
5. 遇到 `Vault not found`，核对微信流所选vault名称与Obsidian已打开的知识库；把目标目录在Obsidian中打开，再用同一份转发重新完成。

原版分享入口由用户手动触发。日常自动读取使用本技能数据库流程。需要多批收集时，按当前微信单次选择上限分批，沿用微信流的“完成并发送”操作。

## 群聊分析场景

用户需要“群聊反诈分析”时，可将 `assets/group-scam-review.zip`导入微信流技能中心，再创建场景并绑定用户给定的准确群名与目标应用。读取实际群消息后，输出有消息依据的判断；具体群名和知识库由当前用户选择。

其他分析场景复用相同记录读取方式，根据当前用户的目标编写分析要求。

## 手机历史迁移

1. 保留当前索引作为迁移前基线，记录账号标识、消息ID和当前数量。
2. 使用微信自带的聊天记录迁移或导出到电脑功能。Android可使用已有ADB协助连接，按设备返回的状态完成连接设置。
3. 手机历史通过微信迁移到电脑后，与电脑已有记录一起建立索引。
4. 用户确认传输完成后执行 `refresh`；完成前保持旧索引可查询。
5. 执行 `wechat.py compare --baseline <迁移前索引路径>`，按迁移前后消息ID比较：重合且保留的记录、新增记录、旧记录缺失、同ID正文或字段变化分别统计。源库重复项另计；相同文字的不同消息保留。
6. 更新会话数量及记录起止时间。迁移已完成并生成本地索引后，后续查询使用电脑数据。

ADB识别不到Android手机时，可检查USB调试授权，再尝试libusb后端和独立端口。

## 排除会话及公众号

使用 CLI 的 `exclude plan --session <准确名称或ID>` 生成当前名单，再运行 `exclude apply --plan <返回路径>`。用户给出的删除名单即为操作范围；重名时按当前请求消歧。`--public-accounts`设置后续公众号排除规则。

脚本保留原索引和规则文件，将选定会话从当前索引排除，并写入当前账号的 `excluded_sessions.json`。原始微信数据由微信管理。后续刷新沿用这些规则，历史备份按所选保留方式管理。

之后运行 `report sessions`更新有效数量，媒体查询使用当前有效消息。
